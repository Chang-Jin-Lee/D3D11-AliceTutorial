# 40. MSAA & Alpha-to-Coverage 설계

39번은 겹치는 반투명 면의 합성 순서를 비교했다. 40번은 같은 캐릭터의 레이스를 보며 기하 경계와 텍스처 알파 경계가 어떻게 달라지는지 비교한다.

사용자가 승인한 범위는 Alpha Test 1x, Alpha Test 4x MSAA, Alpha-to-Coverage 4x MSAA 비교다. 이 문서는 구현 전 설계이며, 구현·테스트·촬영이 끝났다는 기록이 아니다.

- 프로젝트: `Dx11/40_MSAA_AlphaToCoverage`
- 작업 브랜치: `codex/project40-msaa-alpha-to-coverage`
- 기준: 39번 PR #85가 머지된 `main`, `0e4b8a0dffc46e4f22242b71d9eaf501a634048e`
- 빌드: Visual Studio 2022, Direct3D 11, Debug/Release x64

## 학습 목표와 범위

다음 세 가지를 실행 화면과 코드로 확인한다.

1. MSAA가 삼각형 경계의 샘플 커버리지를 어떻게 부드럽게 만드는가.
2. 픽셀 단위 `clip`으로 자르는 텍스처 알파 경계가 MSAA만 켠다고 모두 부드러워지지는 않는 이유.
3. Alpha-to-Coverage(A2C)가 알파를 샘플 커버리지로 바꾸는 방식과, 유한한 샘플 수에서 생기는 단계·노이즈의 한계.

캐릭터만 사용하면 기하 경계와 텍스처 경계를 구분하기 어렵고, 진단 사각형만 사용하면 기존 학습 흐름과 연결이 약하다. 따라서 캐릭터와 간단한 진단 장면을 함께 제공한다. 39번 OIT에 MSAA를 통합하는 방식은 누적·합성까지 주제가 넓어지므로 이번 범위에서 제외한다.

기존 `Common`, `Common/Animation`, 1–39번 렌더링 코드, 모델·텍스처 파일은 변경하지 않는다. 기존 로더와 애니메이터는 그대로 사용한다. 새 라이브러리, 공통 엔진 계층, 심볼릭 링크, junction은 추가하지 않는다. 프로젝트 등록과 README·미디어 도구의 40번 연결은 변경 범위에 포함한다.

## 비교 모드와 화면

| 모드 | 색상·깊이 샘플 수 | 비교 대상 알파 처리 | 비교 대상 블렌딩 / 깊이 쓰기 |
|---|---|---|---|
| Alpha Test 1x | 1 | 알파가 cutoff 미만이면 discard | OFF / ON |
| Alpha Test 4x MSAA | 4 | 1x와 같은 픽셀 셰이더·cutoff | OFF / ON |
| Alpha-to-Coverage 4x MSAA | 4 | 중간 알파를 SV_Target0.a로 출력 | 일반 블렌딩 OFF, A2C ON / ON |

기본 실행은 Alpha Test 1x, 캐릭터 레이스 확대, 카메라 정지다. 모드 변경은 카메라·포즈·조명·배경·노출을 초기화하지 않는다. 같은 해상도에서 모드를 바꾸어 비교한다. 4x 모드끼리 전환할 때 타깃은 재사용한다.

- 캐릭터: 기존 `SampleModel.glb`, 39번과 같은 고정 포즈와 단순 조명. 전신/레이스 확대 구도를 제공한다.
- 진단 장면: 불투명 대각선 경계, 사각형 내부의 알파 경사·가는 줄무늬, 깊이 가림을 확인할 불투명 면을 배치한다. 작은 절차적 텍스처는 앱에서 생성하며 기존 에셋은 바꾸지 않는다.
- `1/2/3`: 비교 모드, `C`: 전신/레이스 확대, `O`: 느린 카메라 회전, `S`: 캐릭터/진단 장면.
- ImGui: 같은 모드·장면·카메라 조작, 비교 대상 알파 배율, Alpha Test cutoff, 배경색, 노출, 샘플 지원·측정 상태.
- 초기 알파 배율은 1, 노출은 1. 캐릭터 cutoff는 원본 레이스 값에서 시작하며 진단 cutoff는 0.5다. 조절한 값은 모드 전환 시 유지한다.
- A2C에서 cutoff 조절은 비활성화한다. Alpha Test의 cutoff를 A2C에도 적용하는 것처럼 표시하지 않는다.
- 키 자동 반복과 ImGui 키보드 입력 중의 단축키 충돌을 막는다.

2x·8x 선택, 화면 분할, 샘플별 확대 뷰, TAA·FXAA, 샘플 주파수 셰이딩, 알파 커버리지 보정 mipmap은 이번에 추가하지 않는다.

## 원본 재질과 비교용 처리

원본 레이스는 glTF `MASK`다. 다음 세 조건이 모두 맞는 재질에만 40번의 비교 처리를 적용한다.

- 재질 인덱스 4
- 전체 이름 `N00_002_01_Tops_01_CLOTH_02 (Instance)` 일치
- 원본 알파 모드 `MASK`

조건이 다르면 다른 재질을 대신 선택하지 않는다. 캐릭터는 원본 재질로 렌더링하고 HUD에 레이스 비교 비활성 이유를 표시한다. 진단 장면은 계속 사용할 수 있다.

비교 입력 알파는 텍스처·baseColorFactor·정점 알파를 반영한 값에 비교용 배율을 곱하고 [0, 1]로 제한한다. 배율은 레이스와 진단 알파 패턴에만 적용한다.

Alpha Test는 선택한 cutoff로 이진 판정하고 남은 색을 불투명하게 쓴다. A2C는 cutoff로 이진화하지 않고 중간 알파를 출력한다. 이는 원본 MASK를 보존한 결과가 아니라 비교용 변경이다. 알파 0은 비교 대상에서 항상 discard하여 cutoff를 0으로 내려도 색·깊이에 기여하지 않게 한다.

다른 OPAQUE/MASK 재질은 원본 모드와 cutoff를 유지한다. 눈 등 원래 BLEND인 재질은 모든 모드에서 중심 깊이 기준 back-to-front 정렬과 straight-alpha OVER를 사용하고, 깊이 테스트 ON·깊이 쓰기 OFF로 그린다. 이 패스에서는 A2C를 반드시 끈다. 샘플 수 변경에 따른 경계 차이는 있어도 재질을 Alpha Test로 바꾸지는 않는다.

A2C는 일반 알파 블렌딩과 별개인 커버리지 처리다. 중간 알파의 정확한 샘플 배치는 하드웨어에 따라 달라질 수 있다. 여러 겹의 반투명 색을 정확히 합성하거나 OIT를 대체한다고 설명하지 않는다. [Microsoft A2C 문서](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d10-graphics-programming-guide-blend-state#alpha-to-coverage)

## 코드 구성과 렌더링 경로

namespace는 `Coverage40`으로 분리한다.

- `App`: 창, 입력, ImGui, 모델과 고정 포즈, 카메라, draw 목록, 표면 셰이더를 소유한다. 애니메이터의 같은 포즈를 스키닝과 BLEND 정렬 중심 계산에 사용한다.
- `CoverageScene`: 레이스 식별, 유효 재질 처리 선택, 투명 draw 정렬을 담당한다. D3D 장치 없이 테스트할 수 있는 작은 함수로 구성한다.
- `MsaaPipeline`: 지원 조회, 색상·깊이 타깃, 깊이·블렌드 상태, Resolve, 최종 출력, 비동기 GPU 측정을 소유한다. Win32/ImGui/Assimp에 의존하지 않는다.
- `40_Surface.hlsl`와 공유 알파 함수: Alpha Test와 A2C의 입력·분기 규칙을 정의한다. 실제 앱과 픽셀 테스트가 같은 함수를 사용한다.
- `40_Present.hlsl`: 선형 색에 노출·톤매핑·sRGB 변환을 적용한다.

```text
불투명·원본 MASK·비교 대상 → 선형 HDR 색상 + 깊이 (1x 또는 4x)
                                      ↓
원본 BLEND → 같은 타깃에 정렬 블렌딩, 깊이 쓰기 OFF
                                      ↓
4x: ResolveSubresource → 단일 샘플 HDR / 1x: HDR 직접 사용
                                      ↓
노출·톤매핑·sRGB 변환 → 단일 샘플 UNORM 백버퍼 → ImGui
```

색상은 `R16G16B16A16_FLOAT`, 깊이는 `D32_FLOAT`를 사용한다. 색상과 깊이의 SampleDesc Count/Quality는 일치해야 한다. 1x는 Quality 0, 4x도 지원 확인 후 Quality 0을 사용한다. 장면 래스터라이저는 MSAA에 맞게 설정하고 sample mask는 전체 샘플을 허용한다. A2C 셰이더는 `SV_Coverage`를 출력하지 않는다.

4x 색상 타깃은 별도의 동일 크기·동일 색상 포맷 단일 샘플 텍스처로 Resolve한다. 깊이는 Resolve하지 않는다. 1x에서는 불필요한 복사 없이 색상 SRV를 직접 사용한다. 백버퍼는 모든 모드에서 단일 샘플이다. [ResolveSubresource 조건](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-resolvesubresource)

텍스처 RGB는 SRV 형식에 맞춰 선형화하고 알파는 감마 변환하지 않는다. MSAA Resolve를 선형 공간에서 수행한 뒤 노출·Reinhard 톤매핑·sRGB 변환을 한 번 적용한다. 최종 UNORM RTV에 sRGB 변환을 중복 적용하지 않는다.

파이프라인의 공개 동작은 초기화, 크기/샘플 구성 변경, 패스 시작, 장면 측정 종료, Resolve, Present, 현재 구성·측정 조회로 나눈다. 표면 draw의 IA·VS·PS·CB·텍스처 설정은 호출자가 담당한다. Resolve/Present는 필요한 바인딩을 직접 설정하고 다음 프레임과 충돌할 SRV 바인딩을 해제한다. 실제 파이프라인을 WARP 테스트에 직접 링크한다.

## 지원 조회와 실패 처리

- `CheckMultisampleQualityLevels`로 색상·깊이 포맷의 4x 지원을 각각 확인한다. HRESULT 성공과 quality level 수가 양수인 조건을 모두 확인한다. 색상 포맷의 render target, sampling, multisample render/resolve 지원도 확인한다. [샘플 지원 조회](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11device-checkmultisamplequalitylevels)
- 4x를 사용할 수 없으면 두 4x 모드를 비활성화하고 이유를 표시한다. 1x로 조용히 대체하고 4x라고 표시하지 않는다.
- 모드 전환에 필요한 새 타깃은 모두 생성한 뒤 교체한다. 생성 실패 시 기존 모드·타깃을 유지하고 오류를 알린다.
- 리사이즈 전에 이전 OM/SRV 참조를 해제한다. 0 크기와 최소화 상태는 렌더링을 건너뛴다. 복원 시 창 크기에 맞춰 재생성한다. 리사이즈 실패로 백버퍼와 타깃 크기가 달라진 경우 정상 구성 복구 전까지 렌더링하지 않는다.
- 모델·필수 셰이더·1x 타깃 초기화 실패는 오류 메시지와 초기화 실패로 처리한다. 장치 제거 오류는 표시하고 종료하며 자동 장치 복구는 범위에 넣지 않는다.
- 타이밍 쿼리만 선택 기능이다. 미지원·준비 중 상태를 표시하고 측정 실패 때문에 렌더링을 중단하지 않는다.

## 측정

GPU 시간은 장면 렌더링과 4x Resolve 구간을 분리한다. 1x Resolve는 실행하지 않으므로 `N/A`로 표시한다. 쿼리는 여러 프레임에 걸쳐 비동기로 확인하고 준비되지 않은 결과를 기다리거나 재사용 중인 쿼리를 덮어쓰지 않는다. 모드/크기 변경 후 이전 구성의 측정값을 새 구성의 값처럼 표시하지 않는다.

측정에는 Present, ImGui, 최종 톤매핑, CPU·드라이버 대기 시간이 포함되지 않는다. 고정 성능 우열을 주장하지 않고 같은 장면·해상도에서 실행 중 값을 비교한다.

타깃 메모리는 현재 활성 구성의 논리적 저장량 추정으로 표시한다. W×H 픽셀에서 1x는 HDR 8바이트와 깊이 4바이트로 `W×H×12`, 4x는 샘플별 색상·깊이와 단일 샘플 Resolve 색상을 합쳐 `W×H×(4×12+8)`바이트다. 계산은 64비트로 하고, 백버퍼·모델·텍스처·드라이버 정렬/압축·전환 순간의 임시 자원을 제외한 값이라고 명시한다. VRAM 실사용량으로 표시하지 않는다.

## 검증 기준

실제 앱 코드와 HLSL을 사용하는 테스트를 먼저 작성한다. 상태 설정 문자열 검색만으로 렌더링 동작을 검증하지 않는다.

### 독립 로직과 WARP 픽셀 테스트

- 레이스의 인덱스·전체 이름·원본 MASK 조건이 모두 일치할 때만 비교 처리가 활성화된다.
- 원래 BLEND와 다른 MASK의 처리·cutoff는 유지되며, 알파 배율이 눈 등에 적용되지 않는다.
- 지원/미지원 조합과 1x/4x 타깃 메모리 산식을 검사한다.
- 빈 장면의 배경, 알파 0의 색·깊이 무변경, 알파 1의 전체 기여, Alpha Test cutoff 양쪽을 픽셀로 검사한다.
- A2C가 허용한 샘플만 깊이를 쓰는지 뒤쪽 표면을 그려 검사한다. 불투명 가림과 A2C 이후 일반 BLEND 패스의 상태 복원도 검사한다.
- 4x Resolve의 해석 가능한 색 평균과 선형 색상 경로를 확인한다. HDR 부동소수점 오차를 허용한다.
- 중간 알파들을 순회해 부분 커버리지 동작을 관찰한다. 특정 알파가 반드시 특정 샘플 비트 패턴을 만든다고 단정하지 않는다.
- 1x↔4x·두 4x 모드 간 반복 전환, 크기 변경, 0 크기 거부 후 유효 크기로 복구를 검사한다.
- WARP의 4x 지원을 먼저 확인한다. 미지원 검사는 skip 사유를 출력하고, 4x 동작을 검사하지 않은 결과를 전체 통과로 보고하지 않는다. 4x 경로의 픽셀 검증은 지원 장치에서 완료해야 한다.

### 빌드와 실행 확인

- VS 2022 Debug/Release x64 빌드, 새 HLSL 엄격 컴파일.
- 동일 구도의 세 모드 캡처와 느린 회전 GIF. 대각선 기하 경계와 레이스 텍스처 경계를 따로 확인한다.
- 원본 BLEND 재질, 레이스 식별 실패 표시, 입력·UI 충돌 방지, 최소화/복원과 리사이즈.
- GPU 측정 상태와 현재 모드·샘플 수·메모리 표시의 일치.
- D3D 디버그 레이어 사용 가능 여부와 수집 범위를 기록한다. 사용하지 못했다면 경고가 없었다고 주장하지 않는다.
- 39번 파이프라인·재질 테스트와 README/미디어 도구 회귀 테스트.

1. 레이스 경계에서 살펴볼 문제와 39번과의 차이.
2. 세 모드와 기하 경계/텍스처 경계 비교.
3. 원본 MASK와 비교용 A2C 처리의 차이.
4. 색상·깊이 샘플 구성, Resolve, 조작 방법.
5. 실행 PNG·GIF와 동일 구도 비교 이미지.
6. 검증 방법, GPU 측정 범위, 샘플 수·하드웨어·시간축 깜빡임에 관한 한계.

실행 이미지는 앱에서 촬영한다. A2C가 레이스 깜빡임을 완전히 제거한다거나 모든 구도에서 더 좋다고 쓰지 않는다. 결과가 비슷하거나 줄무늬·노이즈가 남는 경우도 관찰한 그대로 설명한다.
