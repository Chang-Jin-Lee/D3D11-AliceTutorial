# D3D11 Alice Tutorial 앱 아이콘 및 README 브랜딩 디자인

## 상태

- 날짜: 2026-08-05
- 상태: 대화형 디자인 승인 완료, 작성된 문서 검토 대기
- 적용 대상: `Dx11/TutorialApp.sln`의 37개 애플리케이션 프로젝트, 루트 README, 1~37번 프로젝트 README

## 배경

현재 `GameApp`는 `Dx11/Resource/Icon/Alice.ico`를 실행 디렉터리 기준 상대 경로로 읽어 창 클래스의 큰 아이콘에만 설정한다. 이 아이콘은 타사 게임 캐릭터 얼굴을 사용하므로 공개 배포 자산에서 제거해야 한다. 새 아이콘 원본은 사용자가 직접 만든 VRoid 모델을 ChatGPT에 참조 이미지로 제공해 생성한 그림이다.

현재 실행 모델인 `Dx11/Resource/fbx/Public/MyAlice/Player/SampleModel.glb`는 수영복 복장이고, `SampleModel2.glb`는 이전 기모노 복장이다. 두 모델은 이번 작업에서 수정하지 않는다. 새 아이콘은 얼굴과 토끼 귀만 사용하므로 실행 모델의 복장 차이는 아이콘에 드러나지 않는다.

제공된 흑백 투톤 이미지는 실행 중 스플래시나 로딩 화면이 아니다. 저장소와 각 샘플을 설명하는 README용 로고로만 사용한다.

## 목표

1. 새 캐릭터 이미지를 얼굴·토끼 귀 중심으로 크롭해 Windows 앱 아이콘으로 만든다.
2. 솔루션의 37개 실행 파일, 작업 표시줄, 창 제목 표시줄에 같은 아이콘을 적용한다.
3. 흑백 투톤 로고를 루트와 37개 프로젝트 README의 제목 바로 아래에 배치한다.
4. 공개 파일명에서 `ChatGPT`를 제거해 OpenAI 공식 앱으로 오인될 가능성을 낮춘다.
5. 아이콘과 README 적용 상태를 자동 검증할 수 있게 한다.

## 비목표

- 스플래시 화면이나 로딩 화면을 추가하거나 변경하지 않는다.
- `Loading.png`와 `LoadingDone.png`를 변경하지 않는다.
- `SampleModel.glb`와 `SampleModel2.glb`를 변경하지 않는다.
- 캐릭터 모델의 복장을 바꾸거나 새 3D 모델을 만들지 않는다.
- 솔루션 밖의 오래된 프로젝트를 브랜딩 적용 대상으로 확장하지 않는다.

## 승인된 시각 방향

### Windows 아이콘

선택안은 A안인 얼굴·토끼 귀 중심 크롭이다.

- 수영복과 하체는 완전히 제외한다.
- 얼굴, 눈, 머리카락, 토끼 귀를 크게 보여 작은 아이콘에서도 식별되게 한다.
- 1254x1254 원본에서 `(x=147, y=0, width=960, height=960)` 정사각형을 기준 크롭으로 사용한 뒤 1024x1024 마스터로 리샘플링한다.
- 원본의 흰색 외곽 모서리는 투명 처리한다.
- 최종 정사각형 마스터 PNG에서 16, 20, 24, 32, 40, 48, 64, 128, 256px 프레임을 포함한 다중 해상도 ICO를 만든다.
- 공개 저장소에는 크롭한 마스터와 최종 ICO만 저장한다. 수영복이 보이는 전체 원본 이미지는 복사하지 않는다.

예정 파일:

- `Dx11/Resource/Icon/AliceTutorialIcon.png`
- `Dx11/Resource/Icon/AliceTutorial.ico`

### README 설명 로고

선택안은 A안인 프로젝트 제목 바로 아래 배치다.

- 1536x1024 투톤 원본에서 `(x=0, y=160, width=1536, height=640)` 영역을 잘라 캐릭터 얼굴·귀와 그라데이션을 보존한 가로형 배너를 만든다.
- 최종 파일은 `docs/media/branding/alice-tutorial-logo.png`로 저장한다.
- 루트 README에서는 첫 번째 `# D3D11-AliceTutorial` 제목 바로 아래에 폭 720px로 배치한다.
- 각 프로젝트 README에서는 첫 번째 프로젝트 H1 제목 바로 아래에 폭 520px로 배치한다.
- 대체 텍스트는 `D3D11 Alice Tutorial mascot logo`로 통일한다.
- 실행 화면, 스플래시, 로딩 UI에서는 이 로고를 사용하지 않는다.

README 블록 형식은 다음과 같다.

```html
<!-- README-BRAND:START -->
<p align="center"><img src=".../alice-tutorial-logo.png" width="520" alt="D3D11 Alice Tutorial mascot logo" /></p>
<!-- README-BRAND:END -->
```

루트 README는 `docs/media/branding/...`를, 프로젝트 README는 `../../docs/media/branding/...`를 참조한다.

## Win32 리소스 구조

### 공통 리소스

`Dx11/Resource/Icon`에 다음 공통 파일을 둔다.

- `AppIconResource.h`: 공통 아이콘 리소스 ID
- `AppIcon.rc`: `AliceTutorial.ico`를 참조하는 Windows 리소스 스크립트
- `AliceTutorial.ico`: 다중 해상도 앱 아이콘

기존 `Alice.ico`는 저장소에서 제거한다.

### 37개 프로젝트 자동 적용

`Dx11/Directory.Build.targets`에서 다음 조건을 모두 만족하는 프로젝트에만 `AppIcon.rc`를 `ResourceCompile` 항목으로 추가한다.

1. `ConfigurationType`이 `Application`이다.
2. 프로젝트 이름이 `TutorialApp.sln`의 37개 애플리케이션 프로젝트 중앙 허용 목록에 포함된다.

허용 목록과 솔루션의 애플리케이션 프로젝트 목록이 달라지면 자동 검증이 실패해야 한다. 이를 통해 37개 `.vcxproj`를 개별 수정하지 않으면서 솔루션 밖의 오래된 프로젝트에는 리소스를 주입하지 않는다. `Common` 정적 라이브러리에도 리소스를 주입하지 않는다.

### 런타임 아이콘 로딩

`GameApp::Run`은 파일 경로 대신 현재 EXE의 내장 리소스에서 아이콘을 읽는다.

1. 시스템 큰 아이콘 크기에 맞춰 리소스를 읽어 `WNDCLASSEXW::hIcon`에 설정한다.
2. 시스템 작은 아이콘 크기에 맞춰 별도로 읽어 `WNDCLASSEXW::hIconSm`에 설정한다.
3. 어느 한쪽 로딩이 실패하면 해당 크기에 Windows 기본 애플리케이션 아이콘을 사용한다.
4. 상대 작업 디렉터리나 외부 ICO 파일 존재 여부에 의존하지 않는다.

내장된 첫 번째 애플리케이션 아이콘은 Windows Explorer의 EXE 아이콘에도 사용된다.

## 자산 생성 및 README 갱신 도구

`tools/generate_app_brand_assets.py`는 제공된 외부 원본 경로를 입력받아 다음 최종 자산을 만든다.

- 얼굴·귀 중심의 투명 정사각형 마스터 PNG
- 다중 해상도 ICO
- README용 가로형 투톤 배너

원본 전체 이미지는 저장소에 복사하지 않는다. 체크인된 크롭 마스터와 최종 출력물이 배포 기준 자산이다.

`tools/update_readme_branding.ps1`은 루트와 37개 README를 갱신한다.

- 기존 `README-BRAND` 블록이 있으면 교체한다.
- 블록이 없으면 첫 번째 H1 제목 바로 뒤에 삽입한다.
- 여러 번 실행해도 블록이 중복되지 않아야 한다.
- 기존 `README-NAV`와 `README-INFO` 블록은 변경하지 않는다.

## 오류 처리

- 자산 생성 도구는 입력 이미지가 없거나 디코딩할 수 없으면 출력물을 일부만 남기지 않고 실패한다.
- ICO 필수 프레임 생성에 실패하면 성공으로 처리하지 않는다.
- README 갱신 도구는 대상 H1을 찾지 못한 파일을 보고하고 실패한다.
- 런타임 내장 아이콘 로딩 실패는 Windows 기본 아이콘으로 대체하며 애플리케이션 시작을 막지 않는다.

## 검증 계획

자동 검증은 다음 계약을 확인한다.

1. `AliceTutorial.ico`에 16, 20, 24, 32, 40, 48, 64, 128, 256px 프레임이 모두 있다.
2. `Directory.Build.targets`의 허용 목록과 `TutorialApp.sln`의 37개 애플리케이션 프로젝트가 일치한다.
3. 37개 애플리케이션이 공통 `AppIcon.rc`를 받으며 `Common`은 받지 않는다.
4. 루트 README와 37개 프로젝트 README에 `README-BRAND` 블록이 정확히 한 번 있다.
5. 모든 README 로고 상대 경로가 실제 공통 파일을 가리킨다.
6. `Alice.ico`와 `..\\Resource\\Icon\\Alice.ico` 로딩 참조가 남아 있지 않다.
7. README 갱신 도구를 두 번 실행해도 두 번째 실행에서 추가 변경이 생기지 않는다.

빌드 검증은 `Dx11/TutorialApp.sln`의 x64 구성을 기준으로 한다. 가능한 경우 솔루션 전체를 빌드한다. 환경 의존성으로 전체 빌드가 막히면 공통 코드와 01, 36, 37번 대표 프로젝트를 빌드하고, 전체 빌드를 막은 정확한 외부 의존성을 결과에 기록한다.

## 자산 출처 기록

- 새 캐릭터 그림은 사용자가 직접 만든 VRoid 모델을 참조해 ChatGPT로 생성했다.
- 이번 변경은 타사 게임 캐릭터 기반 기존 아이콘을 제거하는 기술 작업이다.
- VRoid 모델에 별도 외부 의상, 텍스처 또는 부속 자산이 사용되었다면 해당 자산의 라이선스 기록은 사용자가 별도로 보관한다.
- 이 문서는 법적 권리 판단을 대신하지 않는다.

## 수용 기준

- 37개 앱의 EXE, 작업 표시줄, 큰 창 아이콘, 작은 창 아이콘이 새 A안 아이콘을 사용한다.
- 앱 실행은 외부 ICO 파일 경로에 의존하지 않는다.
- 기존 타사 캐릭터 아이콘 파일과 코드 참조가 저장소에서 제거된다.
- 루트와 37개 프로젝트 README의 제목 바로 아래에 동일한 설명 로고가 한 번씩 표시된다.
- 로고는 런타임 스플래시나 로딩 화면에 나타나지 않는다.
- 현재 수영복 모델과 이전 기모노 모델 파일은 변경되지 않는다.
- 자동 검증과 가능한 범위의 x64 빌드 검증 결과가 보고된다.
