# feat: 39번 반투명 비교 예제 추가 — Alpha Test, Alpha Blend, Weighted OIT

### 추가 이유

직접 만든 VRM 캐릭터를 GLB로 내보내 사용 중입니다. 치마 레이스의 중간 알파값으로 Alpha Test, Sorted Alpha Blend, Weighted Blended OIT를 비교합니다.

20번의 깊이·알파 문제, 35번의 MRT, 38번의 캐릭터 재질과 반투명 정렬에서 이어지는 예제입니다.

### 구현 내용

- `39_Transparency_OIT` 프로젝트 추가.
- 같은 캐릭터·포즈·조명에서 세 가지 반투명 처리 방식 비교.
- 교차하는 반투명 사각형 3장과 불투명 가림판 추가.
- Accumulation·Revealage MRT 누적과 선형 HDR 합성 구현. 합성 후 노출·톤매핑·sRGB 변환 적용.
- 레이스 확대, 제출 순서 역전, 카메라 회전, 누적 버퍼 보기 추가.
- CPU 정렬 시간과 GPU 투명·합성 패스 시간 표시.
- WARP 픽셀 테스트 8개와 재질 분류·정렬 동작 테스트 17개 추가. HDR 색 제한 회귀 테스트 포함.
- README 설명과 실행 PNG·GIF, 레이스 비교 화면 추가.

### 레이스 재질 처리

원본 GLB의 레이스는 `MASK` 재질입니다. 기본 모드와 cutoff를 유지하고, `Lace MASK -> BLEND`를 켜면 해당 레이스만 반투명으로 처리합니다. 재질 인덱스와 이름을 함께 확인해 다른 재질에는 적용하지 않습니다.

### 문제 상황과 확인 방법

반투명 면은 깊이 쓰기를 꺼도 그리는 순서에 따라 색이 달라집니다. 서로 교차하는 면은 픽셀마다 앞뒤가 달라서 draw 중심을 기준으로 정렬하는 것만으로는 해결되지 않습니다.

- 레이스: `L`로 반투명 처리를 켜고 `C`로 확대한 뒤 `1/2/3`으로 모드 비교. Alpha Test에서는 경계가 거칠게 잘리고, 블렌딩에서는 중간 알파가 유지됩니다.
- 순서 의존성: `S`로 사각형 장면을 선택하고 `R`로 제출 순서 역전. Sorted 결과는 달라지고 OIT는 작은 누적 오차를 제외하면 거의 같은 결과를 유지합니다. Sorted 모드의 R은 정렬된 목록도 일부러 뒤집는 비교입니다.
- 정면 레이스에서는 Sorted와 OIT가 비슷하게 보입니다. 이 화면만으로 차이를 판단하지 않고 교차 사각형과 순서 역전으로 비교했습니다.
- `O`로 카메라를 회전하고 Accumulation·Revealage 보기로 누적 결과 확인. 최소화·복원과 창 크기 변경도 확인했습니다.

Debug / Release x64 빌드와 자동 테스트는 통과했습니다. Release에는 기존 Common의 VMD 중복 정의 경고(`LNK4006`) 6건이 남아 있으며, D3D11 디버그 메시지 큐 수집은 수행하지 않았습니다.

### 한계와 이후 계획

- OIT는 정확한 픽셀별 정렬 합성이 아닌 근사법이라, 불투명에 가까운 층이 겹치면 색이 섞일 수 있습니다. 후속 작업 후보는 카메라 각도·알파값별 레이스 캡처를 추가해 차이를 비교하는 것입니다.
- FP16 누적이므로 겹치는 층이 많으면 오차나 overflow가 생길 수 있습니다. 층 수와 입력 색 범위를 바꾼 테스트를 늘려 오차를 비교하는 것도 후속 작업으로 제안합니다.
- MSAA/Alpha-to-Coverage는 구현하지 않았습니다. 별도 예제에서 레이스 경계 처리 방식을 비교하는 것을 다음 주제로 제안합니다.
- 반투명 외곽선·그림자는 이번 예제에서 다루지 않습니다. GPU 시간 표시는 해당 패스의 측정값이며 앱 전체 성능을 뜻하지 않습니다.
