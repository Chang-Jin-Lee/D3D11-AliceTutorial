# 17~24번 튜토리얼 기본 캐릭터 시작 로딩 디자인

## 상태

- 날짜: 2026-08-06
- 상태: 대화형 디자인 승인 완료, 작성된 문서 검토 대기
- 적용 대상: 17, 18, 19, 20, 21, 23, 24번 프로젝트

## 배경과 원인

다음 7개 프로젝트는 일반 실행 시 기본 캐릭터가 없는 빈 장면으로 시작한다.

- `Dx11/17_fbx_pmx_obj_WithPhong`
- `Dx11/18_fbx_Animation`
- `Dx11/19_MultiModels`
- `Dx11/20_Depth_And_Alpha_Issue`
- `Dx11/21_MultiModels_With_Animations`
- `Dx11/23_Rigid_Animation`
- `Dx11/24_Skinned_With_Bone_Structure`

각 프로젝트의 `App::OnInitialize()`에는 이미 `SampleModel.glb`를 읽는 코드가 있지만, 로딩 호출 전체가 `ReadmeCapture::IsEnabled()` 조건 안에 있다. 따라서 README 촬영 모드에서는 캐릭터가 보이지만 일반 실행에서는 `LoadModelFromFile()`이 호출되지 않는다.

22번 프로젝트는 비교 가능한 정상 사례다. `SampleModel.glb` 로딩과 원점 배치는 항상 실행하고, README 촬영에 필요한 크기·회전·카메라 연출만 `ReadmeCapture::IsEnabled()` 조건 안에서 적용한다.

## 목표

1. 대상 7개 프로젝트가 일반 실행 직후 현재 기본 캐릭터인 `SampleModel.glb`를 로드한다.
2. 캐릭터의 시작 위치를 월드 좌표 `(0, 0, 0)`으로 유지한다.
3. README 촬영 모드의 기존 크기, 회전, 자동 회전 및 카메라 구도를 보존한다.
4. 모델 로딩 실패 시 잘못된 모델 인덱스에 접근하지 않고 앱 초기화를 계속한다.
5. 같은 문제가 다시 생기지 않도록 자동 회귀 검사를 추가한다.

## 비목표

- `SampleModel.glb` 또는 `SampleModel2.glb` 파일을 수정하지 않는다.
- 기본 캐릭터를 기모노 버전인 `SampleModel2.glb`로 변경하지 않는다.
- 캐릭터의 메시, 재질, 애니메이션 또는 렌더링 파이프라인을 변경하지 않는다.
- 일반 실행에 README 촬영용 크기 `80`, 회전, 자동 회전 또는 카메라 값을 강제로 적용하지 않는다.
- 22번 또는 요청 범위 밖의 프로젝트를 변경하지 않는다.
- 서로 다른 모델 표현을 통합하는 새 공통 초기화 추상화를 만들지 않는다.

## 검토한 접근법

### 1. 로딩과 촬영 연출 분리 — 선택

`SampleModel.glb` 로딩은 항상 수행하고, README 촬영용 시각 설정만 기존 조건 안에 둔다.

- 장점: 일반 실행의 누락만 고치며 기존 촬영 결과를 보존한다.
- 장점: 22번의 검증된 초기화 흐름과 일치한다.
- 장점: 각 프로젝트의 현재 모델 구조를 그대로 사용한다.
- 단점: 비슷한 수정이 7개 `App.cpp`에 반복된다.

### 2. 기존 촬영 블록 전체를 일반 실행에도 적용

`ReadmeCapture::IsEnabled()` 조건을 제거해 로딩과 모든 촬영 연출을 항상 적용한다.

- 장점: 코드 변경량이 가장 작다.
- 단점: 일반 실행에서도 크기 `80`, 강제 회전, 자동 회전 및 촬영용 카메라가 적용되어 튜토리얼의 평상시 조작 환경을 바꾼다.

### 3. 공통 기본 모델 초기화 헬퍼 추가

공통 모듈이 모델 경로, 위치 및 촬영 설정을 관리하게 한다.

- 장점: 기본 경로와 일부 정책을 한곳에 모을 수 있다.
- 단점: 17·18번은 단일 모델 상태를 사용하고 나머지 5개는 `ModelEntry` 목록을 사용하므로 공통 인터페이스가 오히려 복잡해진다.
- 단점: 이번 누락 수정에 필요하지 않은 구조 변경이다.

요구 범위와 기존 구조를 고려해 접근법 1을 사용한다.

## 초기화 흐름

각 대상 프로젝트의 `App::OnInitialize()`에서 Direct3D, 효과, 장면, ImGui, 텍스처 및 시스템 정보 초기화가 끝난 뒤 다음 순서로 실행한다.

1. `..\\Resource\\fbx\\Public\\MyAlice\\Player\\SampleModel.glb`를 `LoadModelFromFile()`로 읽는다.
2. 로딩 성공 여부를 확인한다.
3. 캐릭터를 원점에 둔다.
4. README 촬영 모드일 때만 기존 촬영용 크기, 회전, 자동 회전 및 카메라 값을 적용한다.
5. 성공 여부와 관계없이 기존 앱 초기화 계약에 따라 `OnInitialize()`를 계속 완료한다.

### 17·18번

17·18번은 단일 모델 위치를 `m_modelPos`로 관리한다. `LoadModelFromFile()`은 로딩 성공 시 `m_modelPos`, 크기, 회전을 기본값으로 초기화하며 `m_modelPos`를 `(0, 0, 0)`으로 설정한다. 월드 행렬은 이 값을 이동 행렬에 사용하므로 기본 모델은 원점에 배치된다.

구현은 로딩 성공 블록을 일반 실행 경로로 옮기되, 다음 촬영 전용 값은 `ReadmeCapture::IsEnabled()` 안에 유지한다.

- `m_modelScale = (80, 80, 80)`
- `m_modelRotation = (0, -35, 0)`
- `m_RotateModel = true`
- 촬영용 카메라 위치와 회전

### 19·20·21·23·24번

이 프로젝트들은 로드된 모델을 `m_Models`에 추가하고 `ModelEntry::pos`로 위치를 관리한다. `LoadModelFromFile()`이 성공하고 목록이 비어 있지 않을 때 마지막으로 추가된 모델에 다음을 적용한다.

- `model.pos = XMFLOAT3(0.0f, 0.0f, 0.0f)`는 항상 적용한다.
- `model.scale`, `model.rotDeg`, `model.autoRotate`와 촬영용 카메라는 README 촬영 모드에서만 적용한다.

이 구조는 로딩 실패 후 `m_Models.back()` 또는 고정 인덱스를 참조하지 않는다.

## 오류 처리

- 기본 모델 파일이 없거나 로더가 실패하면 모델별 후속 설정을 건너뛴다.
- 로딩 실패만으로 앱 전체 초기화를 실패시키지 않는다. 사용자는 기존 모델 찾아보기 UI로 다른 파일을 선택할 수 있다.
- 목록 기반 프로젝트는 `LoadModelFromFile()` 성공과 `!m_Models.empty()`를 모두 확인한 뒤 `back()`에 접근한다.
- README 촬영 모드에서도 로딩 실패 시 촬영용 모델·카메라 설정을 적용하지 않는다.
- 새 예외, 팝업 또는 공통 오류 처리 계층은 추가하지 않는다.

## 테스트 설계

먼저 현재 코드에서 실패하는 PowerShell 회귀 테스트를 추가한다. 테스트는 대상 목록을 중앙에 정의하고 각 `App.cpp`의 초기화 계약을 검사한다.

1. 대상이 정확히 17, 18, 19, 20, 21, 23, 24번인지 확인한다.
2. 각 대상이 일반 실행 경로에서 정확한 `SampleModel.glb`를 로드하는지 확인한다.
3. 모델 로딩 호출이 `ReadmeCapture::IsEnabled()` 블록에 종속되지 않는지 확인한다.
4. 19·20·21·23·24번은 로딩 성공 후 마지막 모델의 위치를 `(0, 0, 0)`으로 명시하는지 확인한다.
5. 17·18번은 로딩 성공 경로가 `m_modelPos`를 `(0, 0, 0)`으로 초기화하고 시작 코드가 이를 다른 위치로 덮어쓰지 않는지 확인한다.
6. 촬영용 크기, 회전, 자동 회전 및 카메라 설정은 계속 `ReadmeCapture::IsEnabled()`에 종속되는지 확인한다.

테스트가 누락 원인 때문에 실패하는 것을 먼저 확인한 후 최소 코드 변경을 적용하고 같은 테스트가 통과하는 것을 확인한다. 이후 대상 7개 프로젝트를 Debug/x64로 빌드한다. 실행 파일은 일반 환경에서 짧게 기동해 모델 로딩 실패나 즉시 종료가 발생하지 않는지 확인하며, 가능한 경우 창 캡처로 시작 장면의 캐릭터 표시도 점검한다.

## 수용 기준

- 17, 18, 19, 20, 21, 23, 24번을 일반 실행하면 `SampleModel.glb`가 자동으로 로드된다.
- 시작 캐릭터의 월드 위치는 `(0, 0, 0)`이다.
- 일반 실행에는 README 촬영용 크기·회전·자동 회전·카메라가 강제되지 않는다.
- README 촬영 모드의 기존 연출은 유지된다.
- 모델 로딩 실패 시 유효하지 않은 모델 인덱스에 접근하지 않는다.
- 새 회귀 테스트와 대상 7개 Debug/x64 빌드가 통과한다.
- `SampleModel.glb`, `SampleModel2.glb` 및 사용자 소유의 `.superpowers/` 파일은 변경하거나 커밋하지 않는다.
